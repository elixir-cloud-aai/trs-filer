This release moves TRS-Filer to FOCA 0.23.0 and TRS 2.0.2, and adds
access control: writes need an access token, the user registering a tool
owns it and can share it, and admins can control or moderate who adds tool
classes. File contents can be stored in S3-compatible object storage, and
I/O Schemas of workflows can be registered and checked (experimental). The
Helm chart is rebuilt on FOCA's library chart, with camelCase values.
Several changes are breaking for deployments, clients and custom configs:
releases of earlier charts can't be upgraded but must be reinstalled, and
the app refuses to start until its identity provider and admin group are
set. Read the [upgrade steps from
0.5.0](https://trs-filer.readthedocs.io/en/v0.6.0/upgrading/#from-050)
**before** upgrading. See the
[documentation](https://trs-filer.readthedocs.io/en/v0.6.0/) for details.

## Breaking changes

- Access control: registering, changing and deleting tools, versions and
  tool classes need an access token (RFC 9068, `at+jwt`) of a trusted
  OpenID Connect provider (`401` without one); reads stay public. The app
  refuses to start until the deployment sets its identity provider and
  admin group (`security.auth`, `security.access_control`; with the Helm
  chart, the value `config`) (#7, #280)
- Access control: the user registering a tool owns it; owners grant the
  roles `owner` and `maintainer` to users and groups
  (`/tools/{id}/permissions`), and admins can do everything. Tools stored
  before have no owners, so only admins can change them until an admin
  grants owners (#86, #283)
- FOCA 0.23.0 (from 0.22): users are identified as
  `<namespace>|<sub>`, the `sub` claim of their tokens namespaced by the
  issuer, also with a single trusted issuer, in roles, permissions URLs and
  `user:` subjects of config overlays; writes without a valid token get
  `401` before their body is checked (also for too large bodies); `null`
  in `patches` of config overlays removes the key (#318, #317)
- Helm chart: a thin chart over FOCA's library chart `foca-common`, with
  camelCase values (e.g., `trsFiler`, `hostName`, top-level `config`),
  resources named after the release and no configuration Job; releases of
  earlier charts can't be upgraded: uninstall them and install the new
  chart, moving the data as described in the upgrade steps (#135, #284)
- API: the served specification is that of TRS 2.0.2 (before: a commit of
  TRS `develop`), and the service info reports TRS version `2.0.2`; config
  overlays that set `api.specs.trs.path` or patch its operations must
  follow (#272, #276; #308, #309)
- API: `{type}/descriptor`, `{type}/descriptor/{relative_path}` and
  `{type}/tests` check `Accept`: clients that don't accept the media type
  of the type get `406` instead of a response they didn't ask for (#74,
  #281)
- Config: users other than admins may have added at most 10 tool classes
  that no tool has (`custom.access_control.max_unused_tool_classes`;
  `null` for no limit); further ones get `409` (#177, #286, #290)
- Config: `custom.toolclass.validation: true` is deprecated and now sets
  the mode `controlled` (only admins add tool classes, also by registering
  tools), with a warning on startup (#248, #289)

## Features

- Config: the modes `controlled` and `moderated` of
  `custom.access_control.tool_classes`; in `moderated`, tool classes of
  other users, and their tools, are pending until an admin approves them
  (`PUT /toolClasses/{id}/approval`), and `GET /approvals` lists them,
  paged as `GET /tools` (#248, #289; #298, #299)
- Storage: file contents can be stored in S3-compatible object storage
  (`custom.storage.backend: s3`); by default (`mongodb`), nothing changes
  (#141, #288)
- API: GA4GH I/O Schemas of workflows (experimental): files of the new
  type `IO_SCHEMA` (an extension of TRS) and the option
  `custom.io_schema.validation`, which checks them on registration against
  the meta-schema of the GA4GH I/O Profile 0.3.0, in time about linear in
  their size (#277, #282; #285, #287; #300, #301; #312, #313)
- API: the descriptor type `SMK` (Snakemake), tags of tools (filter `tags`
  of `GET /tools`) and descriptions of tool versions; the served
  specification has the app's `info` (title, license and contact) (#271,
  #273)
- API: versions of the languages of tool versions
  (`descriptor_type_version`), and the reads declared public in the served
  specification (#272, #276)
- API: descriptors and tests are served as plain text for the `PLAIN_`
  types, with `Vary: Accept` (#278, #279; #74, #281)

## Security

- Image: dnspython 2.9.2, which fixes excessive memory and CPU use when
  parsing malicious WKS records (#291)
- Release workflow: re-running all jobs of a published release can't move
  its image tags to a new digest, and the release check refuses
  dependencies from sources other than PyPI releases (`[tool.uv.sources]`,
  other indexes, non-registry packages in `uv.lock`) (#310, #311; #314,
  #315)

## Fixes

- API: `{type}/descriptor/{relative_path}` finds files in subdirectories by
  encoded and by plain paths, instead of `404` (#278, #279)
- API: the served specification states `info.version: 2.0.2`, as the
  service info, instead of the `2.1.0` of the TRS specification file (#308,
  #309)
